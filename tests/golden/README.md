# Golden-тест парсера контактов

Регрессионный набор: гоняет **реальный** извлекающий пайплайн на **замороженном HTML**
конкретных сайтов и проверяет результат. Цель: каждая правка экстрактора
(эвристика *или* будущая нейронка) судится **числом**, а не «на глаз» по скриншоту.
Это автоматизация ручного A/B-сравнения на 241 сайт.

## Как устроено

```
tests/
  conftest.py              # bootstrap env (pytest tests/ работает без ручных переменных)
  fixtures/html/*.html     # замороженные страницы (общие с integration-тестами)
  golden/
    harness.py             # run()/summarize() — прод-функции, без сети
    cases.yaml             # МАНИФЕСТ: какие фикстуры + какие метки
    test_golden.py         # параметризованный тест по cases.yaml
    snapshots/*.json       # заморожённый вывод (страховка от регресса)
tools/save_fixture.py      # скачать HTML страницы в fixtures/html/
```

Три уровня проверки на кейс:
1. **`min_people`** — счётчик: «на странице ≥ N человек». Дёшево размечается (одно число).
2. **`must_find` / `must_not_find`** — точечные подстроки (фамилия, email, ИНН / мусор).
3. **snapshot** — полная сводка в `snapshots/<id>.json`; падает на *любом* изменении вывода.

## Запуск

```bash
pytest tests/golden -q                      # прогнать набор
GOLDEN_UPDATE=1 pytest tests/golden -q      # принять текущий вывод как новый baseline
pytest tests/golden -k rikor -q             # один кейс
```

- Нет файла фикстуры → кейс **SKIP** (скелеты из писем клиента ждут HTML).
- Snapshot ещё не создан → создаётся, кейс **SKIP** («review & commit»). Прогоните ещё раз — станет PASS.
- Вывод изменился → тест **FAIL** с подсказкой. Осознанное изменение принимается через `GOLDEN_UPDATE=1`.

## Как пополнять набор

1. Сохранить HTML страницы (JS-сайт — добавить `--browser`):
   ```bash
   python tools/save_fixture.py <url> <имя_без_расширения>
   ```
   При ошибке (бот-блок, хитрый JS) — сохранить вручную из браузера («Сохранить как» → HTML) в `tests/fixtures/html/`.
2. Добавить кейс в `cases.yaml`:
   ```yaml
   - id: site_kontakty
     file: site_kontakty.html
     url: https://site.ru/kontakty
     page_score: 20        # для руководящих/контактных страниц (URL-score часто неточен)
   ```
3. Прогнать — snapshot забутстрапится, кейс SKIP:
   ```bash
   pytest tests/golden -k site_kontakty -q
   ```
4. Открыть `snapshots/site_kontakty.json`, проверить найденное, выставить метки в `cases.yaml`:
   - `min_people: N` — floor «не регрессировать» (целевое значение — в `notes`);
   - `must_find` / `must_not_find` — обязательные / запрещённые подстроки (фамилия, email, ИНН / мусор).
5. Перепрогнать → PASS. Закоммитить фикстуру + снапшот + кейс.
6. После осознанного изменения вывода (фикс бага) — принять новый baseline:
   ```bash
   GOLDEN_UPDATE=1 pytest tests/golden -k site_kontakty
   ```

**Стратегия:** покрывать структурные формы (таблица / 2 колонки / карточки / плоский текст / JS / PDF / 404), ~2–3 примера на форму, а не 200 случайных. Ценны «не такие, как все» страницы. Фикс бага → его repro-сайт добавляется в набор.

Примечание: часть сайтов недоступна из dev-сетки (см. `HANDOFF.md`), трудные страницы надёжнее сохранять из браузера на машине с доступом.
