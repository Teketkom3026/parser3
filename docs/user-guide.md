# parser3 — руководство пользователя

Парсер контактов лиц, принимающих решения (ЛПР), с корпоративных сайтов. Ты
даёшь ему список сайтов — он обходит их, вытаскивает ФИО, должности, телефоны,
email, соцсети и реквизиты компаний, раскладывает по ролям и отдаёт готовый
Excel-файл.

Извлечение полностью классическое: обход страниц, разбор HTML, словарь
должностей, морфология и нечёткое сопоставление. **Никакого ИИ/нейросетей
внутри нет** — всё детерминировано.

> **Где открыть.** Приложение живёт по субпути на сервере: рабочая (dev) версия —
> `/parser3-dev/`, стабильная (prod) — `/parser3/`. Обе — один и тот же
> интерфейс. Доступ закрыт паролем (Basic Auth), логин/пароль спросит браузер.

## С чего начать

На главной странице — форма **«Новая задача»**. Скормить сайты можно двумя
способами; оба создают одну задачу.

**Способ 1 — вставить список.** В большое текстовое поле — по одному
сайту/домену на строку. Правила:

- строка без `http://` / `https://` автоматически дополняется до `https://`;
- пустые строки игнорируются;
- строки, начинающиеся с `#`, считаются комментариями и пропускаются.

**Способ 2 — загрузить файл** `.csv` или `.txt` (кнопка «Загрузить CSV/TXT»).
Разбор построчный:

- из CSV берётся первый «похожий на ссылку» кусок строки (тот, где есть точка);
- строки-заголовки (`url`, `сайт`, `site`, `website`, `домен`) пропускаются;
- строки с `#` пропускаются.

> **Дубликаты схлопываются.** Одинаковые URL внутри одной задачи объединяются.
> Поэтому «строк в файле» почти всегда больше, чем «уникальных сайтов» в задаче —
> это нормально, а не потерянные данные.

Ограничения на размер файла — до 50 МБ. Жёсткого потолка на количество сайтов в
задаче нет.

## Режимы парсинга

В форме есть селект **«Режим»** с двумя вариантами.

### Все контакты (`all_contacts`)

Тянет все найденные контакты со всех обойденных страниц сайта. Глубина обхода —
до 15 страниц на сайт. Бери, когда нужна полная выгрузка по компании.

### По списку должностей (`target_positions`)

Появляются 4 чекбокса групп должностей:

- Генеральные директора;
- Финансовые директора;
- Главные бухгалтеры;
- Главные инженеры.

Контакт остаётся в результате, только если его должность (как на сайте или после
нормализации) содержит одно из ключевых слов выбранных групп (`генеральный
директор`, `финансовый директор`, `главный бухгалтер`, `главный инженер`,
`президент` и т.п.). Компания-«заглушка» без ФИО всё равно добавляется — чтобы
сайт не потерялся из отчёта.

> Есть ещё внутренний ускоренный режим `fast_start` (обход 6 страниц вместо 15),
> но в интерфейс он не выведен.

## Что на выходе

На каждую задачу формируется **один XLSX-файл** (`parser3_<номер задачи>.xlsx`).
Плюс контакты можно смотреть прямо в интерфейсе и выгрузить в CSV.

| Формат | Что содержит | Как получить |
|---|---|---|
| **XLSX** | всё: 8 листов с ролями, сводкой и качеством | кнопка «Скачать XLSX» |
| **CSV** | только лист «Все контакты», разделитель `;`, UTF-8 | кнопка «Скачать CSV» |
| Просмотр в UI | первые 500 контактов задачи | страница задачи |

Экспорта в JSON нет (JSON отдаёт только API «вживую»).

### Листы XLSX

Файл состоит из 8 листов:

1. **Генеральные директора**
2. **Финансовые директора**
3. **Главные бухгалтеры**
4. **Главные инженеры**
5. **Остальные** — всё, что не попало в ролевые листы
6. **Все контакты** — плоский полный список
7. **Сводка** — параметры задачи и счётчики по каждому листу
8. **Отчёт качества** — метрики полноты: сколько контактов с ФИО, с должностью,
   с телефоном, с email, с ИНН; сколько `partial` / `error`; разбивка по методу
   нормализации

> **Как контакт попадает в ролевой лист.** Только если распознано непустое ФИО
> **и** нормализатор отнёс должность к этой роли. Иначе — в «Остальные».
> Заместители и «исполнительные директора» в ролевые листы **не** попадают
> (они в списке исключений) — это by design, а не баг.

### Колонки контакта (29 штук)

Порядок в XLSX точный:

```
№ · Компания · Сайт · ИНН · КПП · ОГРН · Наимен. по реквизитам ·
Общий email · Общий телефон · ФИО (полностью) · Фамилия · Имя · Отчество ·
Имя Отчество · Пол · Фамилия И.О. (дат.) · Окончание · Должность (как на сайте) ·
Должность (норм.) · Категория отрасли · Метод нормализации · Личный email ·
Личный телефон · Соцсети · URL источника · Язык · Дата · Статус · Комментарий
```

Отдельно стоит понимать пары «сырое / нормализованное»:

- **Должность (как на сайте)** — как написано на странице; **Должность
  (норм.)** — приведённая к каталогу.
- **Фамилия И.О. (дат.)** — фамилия с инициалами в дательном падеже (для писем
  «кому: Иванову И.И.»); **Окончание** — подобранное окончание.
- **Пол** определяется по ФИО автоматически.

## Как читать результат и следить за задачей

### Страница задачи

Открывается по клику на задачу в таблице. На ней:

- **статус-бейдж** и **прогресс-бар** — считается по *уникальным* сайтам (после
  схлопывания дубликатов), плюс «Сейчас: <адрес>» и оценка оставшегося времени
  (ETA);
- кнопки **Пауза / Продолжить / Отменить**;
- кнопки скачивания: **XLSX**, **CSV**, **исходный файл**;
- таблица **«Сайты»** — по каждому статус и, если была ошибка, её причина;
- таблица **«Контакты»** — первые 500 (полный список — только в XLSX).

Обновления идут «вживую» (через WebSocket) плюс подстраховка опросом раз в 3
секунды. Список задач на главной обновляется раз в 5 секунд.

### Статусы задачи

`pending` (в очереди) → `running` (обрабатывается) → `completed` (готово).
Промежуточно возможны `paused` (на паузе), `cancelled` (отменена), `failed`
(упала целиком).

### Статусы и цвета по сайтам

| Статус | Значит |
|---|---|
| `ok` | сайт обработан, контакты найдены |
| `partial` | данные компании есть, но персональных ФИО не нашли — строка **жёлтая** |
| `error` | сайт не удалось обработать — строка **красная** |
| `pending` / `processing` | ещё в очереди / в работе |

### Почему сайт не спарсился (коды ошибок человеческим языком)

| Код | Что произошло |
|---|---|
| `dns_nxdomain` | домен не существует |
| `dns_timeout` | DNS не ответил вовремя |
| `ssl_error` | проблема с HTTPS-сертификатом |
| `conn_refused` / `conn_error` | сервер отклонил соединение / сетевая ошибка |
| `connect_timeout` / `read_timeout` / `timeout` | сайт слишком медленный |
| `http_403` | доступ запрещён (403) |
| `http_429` | сработала защита от частых запросов (429) |
| `http_4xx` / `http_5xx` | прочие ошибки клиента / сервера |
| `empty_html` | страница пустая, парсить нечего |
| `fetch_failed` / `exception` | не удалось загрузить / внутренняя ошибка |

При таймауте строка сайта оранжевая, при NXDOMAIN — жёлтая, остальное красным.

## Чёрный список

В приложении есть чёрный список — исключения, которые выкидываются из
результатов. Добавить/убрать можно четыре типа записей:

- **должность** — не тянуть контакты с такой должностью;
- **ФИО** — исключить конкретного человека;
- **email** — исключить адрес;
- **домен** — целиком игнорировать сайт.

Полезно, когда в выгрузку раз за разом лезет мусор (тех-поддержка, общие
почтовые ящики, «дежурные» ФИО).

## Что важно помнить

- **ИИ внутри нет.** Качество зависит от того, насколько аккуратно контакты
  размечены на самом сайте (таблицы «должность — ФИО», карточки руководства).
- **В UI видно только 500 контактов** — за полным списком всегда в XLSX.
- **Дубли сайтов схлопываются** внутри задачи — не пугайся расхождения чисел.
- **Замы и и.о. не идут в ролевые листы** — ищи их в «Остальных».
- **Пароля/лимита запросов в самом приложении нет** — доступ закрывает пароль на
  уровне сервера (браузер спросит при входе).
